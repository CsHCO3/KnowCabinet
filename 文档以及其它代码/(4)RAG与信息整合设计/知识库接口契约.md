# 知识库接口契约（infosystem × ragsearch）

> 给接口 AI：基于 `backend/services/ragsearch/service.py` 设计 API 端点与前端。
> 数据组织/检索系统/加新内容类型的扩展指南见 `知识库与检索系统设计.md`（权威活文档，取代旧 `知识库设计决策.md`、`知识库设计方法.md` 的落地状态）。
> 本文档是**运行时契约**（函数签名、返回形状、过滤语义）。

## 1. 知识库一览（registry.json → 目录，三层结构见 知识库与检索系统设计.md）

| KB 名 | 数据目录（相对项目根） | source_type | 内容 | doc_id |
|---|---|---|---|---|
| `dense` | `knowledgebase/dense` | `paper`/`video`/`docs` | **L1 高浓度**：论文浓缩 / 视频摘要 / 精选全文（frontmatter 带 `id`） | `id` = arxiv_id/bvid/slug |
| `papers` | `knowledgebase/full/papers` | `paper` | **L2 全文**：论文最优完整版 | 目录名=arxiv_id |
| `docs` | `knowledgebase/full/docs` | `docs` | **L2 全文**：个人文档 | 目录名 |
| `runoob` | `knowledgebase/full/web/runoob` | `web` | **L2 全文**：网站教程 | 首段目录 |
| `newapi` | `knowledgebase/full/web/newapi` | `web` | **L2 全文**：网站教程 | 文件名 |

二进制（paper.pdf/images）在 `data/papers/{id}/`（L3，不入 KB）；dense 是语义/嵌入源，full 是 BM25 源。

新增源类型 = `knowledgebase/<类型>/` + `ragsearch/registry.json` 加一条 dict（可带 title_weight/body_weight/tag_boost），无需改引擎。

**papers KB 版本策略**：每篇论文只保留 **1 个最优完整版 + condensation.md**。完整版优先级：`cn_paper_ocr.md` > `paper_ocr.md` > `cn_paper.md` > `paper.md`；低级版本/冗余副本移到 `data/_kb_legacy/{id}/`（不入 KB）。检索时 `group_by_doc=True` 把完整版 + 浓缩折叠为一条。

> 现状（2026-08-10）：B站数据已清空（videos KB 为 0 篇，等批量导入）；output/ 已删；旧 `data/papers|videos|docs` 副本待确认后删。

## 2. Frontmatter（引擎认 8 字段）

`id / title / source / section / authors / year / tags / source_type`

- `section`：子串过滤；`authors`：子串过滤；`tags`：逗号分隔精确集合任一命中；`year` / `source_type`：精确字符串（均大小写不敏感，条件 AND）
- `source_type` 取值：`paper` / `video` / `docs` / `web` / `social` / `chat`
- 论文 `tags` 含 primary_category + 浓缩关键词；`section` 为 primary_category 映射大类

## 3. 服务入口（`backend/services/ragsearch/service.py`）

纯 Python 薄封装（不启动 HTTP，直接 import ragsearch 引擎）。所有函数结果均为 **JSON 可序列化** dict/list。

```python
load_registry() -> dict[str, str]
    # 重载 registry.json → {kb: 绝对目录}

rebuild_kb(name: str) -> dict
    # 强制重建某库索引；目录不存在/未登记返回 error 而非抛错
    # → {"status": "ok"|"error", "kb_name": str, "doc_count": int, "error": str|None}

search_kb(name, query, top_k=10, *, section=None, tags=None, year=None,
          authors=None, source_type=None, group_by_doc=False) -> list
    # 单库搜索（query 为必填非空串）

search_all(query, top_k=10, *, section=None, tags=None, year=None,
           authors=None, source_type=None, group_by_doc=False) -> list
    # 跨库搜索；filename 带 [kb] 前缀，按 score 降序合并、去重

get_status() -> dict[str, dict]
    # → {kb: {"doc_count": int, "docs_dir": str, "index_ready": bool}}
```

### 返回形状

`SearchResult`（dict）：
```json
{"filename": "2101.10856/paper.md", "doc_id": "2101.10856", "title": "...",
 "snippet": "命中片段（**高亮**）", "score": 0.78, "rank": 1,
 "section": "Security & Cryptography", "source": "https://arxiv.org/abs/...",
 "authors": "Hao Xu, ...", "year": "2023", "tags": ["cs.CR", "..."],
 "source_type": "paper"}
```

`GroupResult`（dict，`group_by_doc=True` 时）：
```json
{"doc_id": "2101.10856", "title": "...", "score": 0.78,
 "version_count": 2, "versions": [SearchResult, ...]}
```
同论文的 paper.md / cn_paper.md / paper_ocr.md / condensation.md 折叠为一条（共享 doc_id=目录名）。

### 推荐默认值

- papers 检索建议 `group_by_doc=True`（折叠同论文多版本）
- 单库检索用 `search_kb`；跨类型用 `search_all`（结果自带 `[kb]` 前缀可区分来源）

## 4. 归档/浓缩后的索引一致性

- `python -m backend.main archive` 收尾自动 `rebuild_kb("papers"|"videos"|"docs")`（失败记入 report，不阻塞）
- `python -m backend.main condense` 收尾自动 `rebuild_kb("papers")`
- 引擎自带 manifest 增量：md 增/删/改后，**下次搜索自动重建**（无显式 reindex 也能搜到新内容，只是首次会慢一点）
- 也可显式 `POST /kb/{name}/reindex`（若走 ragsearch.server）或调 `rebuild_kb`

### 6.2 `kb-inventory`

```text
kb-inventory [--topic TOPIC] [--tag TAG] [--view snapshot|gap|recent] [--days N] [--pretty]
```

- 默认返回 snapshot dict：`kind/topic/tag/total_docs/by_tier/by_stage/by_source_type/tag_counts/org_counts/generated_at`。
- `--pretty` 返回紧凑文本：`[cbac] 148 条｜L0仅元数据 77｜L1轻整理 0｜L2已提炼 0｜L3全文 71｜paper 148` + 「子方向」行（tags）+ 「项目线」行（`org_counts`，D32；口径注明含 M2 遗留的 arXiv 分区码）。
- `--view gap` 返回按 tag 的 L0–L3 透视；`--view recent` 返回最近更新。
- M2 后 `--tag` 匹配 canonical（中文别名已归一）。

### 6.3 `kb-rebuild`

```text
kb-rebuild [--keep-vector]
```

删除 kb.db（含 WAL/SHM）后完整重建；返回 `{dropped:true, scan_report, embed_report:{}, row_counts, invariants}`。`--keep-vector` 是 M4 向量容器预留参数。
**M3 修复**：此前两处裸 `sqlite3.connect()` 未设 `row_factory`，导致 `assert_invariants` 抛 `TypeError`、命令必炸（退出码 2）；现统一走 `db.connect()`，并有不变量违规时以退出码 2 + stderr 报错（不静默成功）。

### 6.4 `kb-tags`

```text
kb-tags stats|draft|clean --topic TOPIC [--top-k N] [--min-count N] [--apply] [--pretty]
```

- `stats`：返回 DB tags、源 md frontmatter 频次、格式/组织标记/arXiv 分类异常清单。
- `draft`：从现有 DB tags + md frontmatter 生成 `knowledgebase/_meta/vocab/{topic}.json`；`canonical` 只来自已有 tag，另给复数/大小写/-based 合并建议；不调用 LLM、不造新词。
- `clean`：缺省 dry-run。confirmed 词表未覆盖的 `unmapped_tags` 非空或存在 review 文件时，`--apply` 拒绝写回；写回前每个 md 自动生成 `.bak-kb-tags-UTC时间`，只改 frontmatter 的 tags/org_marks/arxiv_tags。
- **M3 修复（重要）**：写回器此前对**已存在**的 `org_marks:`/`arxiv_tags:` 行直接跳过，导致计划中的组织标记被静默丢弃、只留在派生库；规划器也只看 `tags:` 行，因此不幂等、漂移无法自愈。现：规划器读三行求"已有 ∪ 新拆出"的期望态，写回器覆盖已有行。
- `vocab` **DB 表已废弃**（用户决定）：受控词表真相是 `knowledgebase/_meta/vocab/{topic}.json`，不做双写。
- M2 状态：cbac/dairy 已 confirmed 并 apply；vera/ima 目录层已删除；ai-agent draft 暂缓，支持后续动态追加 canonical/aliases。

### 6.5 `kb-ask`（M3 起，M5 加向量支路）

```text
kb-ask QUERY [--topic T] [--tags a,b] [--org a,b] [--source-type a,b]
             [--year Y] [--tier-min N] [--tier-max N] [--stage S]
             [--mode browse|balanced|deep] [--top-k N]
             [--fusion norm|rrf|interleave|reserve] [--fold max|top3sum]
             [--vector] [--no-vector] [--pretty]
```

- 返回 AskResult：`{query, mode, filters, groups[], stats{candidates, returned, by_tier, fusion, vector}}`。
- **查询串内部强制经 `ftx.tokens()` 分词**（与写入端同一套 jieba 搜索引擎模式）；实测未分词的原始连续串 `MATCH '判决树'` 命中 0 条，故这是硬约定，有单测锁定。
- 召回分派：`best_tier=0` 的候选只在 `title_t/abstract_t/tags_t` 上匹配（不搜 body）；`1-3` 走全列。FTS5 列权重 `title 3.0 / abstract 1.5 / tags 2.0 / body 1.0`；tag 命中查询词 +0.5/个（cap +2）。
- **向量支路（M5，仅 deep 默认开启）**：query 嵌入一次（`bge-m3@local-1024`，进程内常驻 + query 级缓存）→ 候选 doc 集内 chunk KNN（vec0 取回 200 块，应用层按确定性过滤集收敛）→ chunk→doc 折叠（`--fold max` 同 doc 取最高块分；`top3sum` 为实验口）。`--vector/--no-vector` 可强制开/关（诊断用）；向量不可用时**降级纯 FTS** 并在 `stats.vector.error` 记账。
- 合并：每档内**每支路** min-max 归一化 → 按 §9.2 配额取（D33 V4：`browse 6/2/1/1`、`balanced 2/3/3/2`、**D49 deep 1/7/1/1**——密度序下"细节"是 tier=1；top_k≠10 按比例缩放、每档至少 1）→ 全局按分数排序（并列优先深档）→ 同 doc 折叠 → 截断 top_k。
- **`--fusion`（默认 `reserve`，D34）**：`reserve`=每档留 1 个名额给向量支路最佳（跨语言保底）；`norm`=两支路取归一化 max（M3 行为）；`rrf`=倒数秩融合（**实测不采用**，跨语言会崩）；`interleave`=两支路轮转取名额。browse/balanced 默认不开向量 ⇒ 行为与 M3 完全一致。
- `--org`（D32）：按 `documents.org_marks` 任一命中过滤，用于"项目线/二级分组"视角；M4 起 arXiv 分区码（`cs.CR/cs.DC` 等）已分流到 `documents.arxiv_cats`，不再混入 org_marks。
- `group` 字段（M5 增补为 additive）：`sources`（`fts`/`vector`）、`fts_score`、`vector_score`、`matched_chunks[]`（含 chunk_id/version_id/tier/kind/chunk_index/score/text）、`quote_chunk_ids[]`（属于 `quote_tier` 的命中块，可直接喂 `kb-fetch --tier <quote_tier> --chunk-ids`）。
- `group.evidence` 证据字段（**D44 口径，2026-10-19**）：`quote_from`（`raw`=有原文版本可引原话 / `derived`=只有整理或提炼版 / `none`=只有元数据）、`quote_tier`（去取原话的档位，raw 时恒为 1）、`quote_kind`、`verbatim_allowed`（=`quote_from=="raw"`）、`l0_only`（仅元数据，只能断言存在性）、`legacy_l2`（D27 豁免标记）。**旧字段 `has_l2`/`has_linked_l2`/`must_quote_l3`/`has_l3`/`quote_fallback` 已移除。**
- 空/纯符号查询返回空 `groups`（不报错）；未知 `mode`/`fusion`/`fold` / `top_k<1` 返回退出码 1。

### 6.6 `kb-fetch`（M3 起，M5 加段落级取证）

```text
kb-fetch DOC_ID [--tier 0-3] [--chunk-ids a,b] [--context N] [--pretty]
```

- 不带 `--chunk-ids`：返回 `{doc_id, tier, kind, path, title, abstract, topic, source_type, best_tier, content, char_count, meta_only, chunks[], segments[]}`（整篇，向后兼容）。
- 带 `--chunk-ids`（M5 生效）：返回 `{segments:[{chunk_id, version_id, tier, kind, path, chunk_index, total_chunks, text, char_count, context_before[], context_after[], prev_chunk_id, next_chunk_id, embedded}], segment_count, context}`，**`content=""` 不给整篇**（02 §11.3 第 3 条：L3 命中只给命中段落 ± 上下文）。块定位 = `path` + `chunk_index/total_chunks` + 前后块 id。
- 错误语义：`chunk_not_found`（块不属于该 doc）、`chunk_not_in_tier`（块不属于指定档）、`invalid_chunk_id`（非整数）、`tier_not_available`、`not_found`、`ambiguous_doc_id`。
- 缺省取最高档；同档多 kind 时按 `paper > cn_paper > paper_ocr > cn_paper_ocr` 择优（原文优先于译文）。
- **L0 空壳**：`meta_only=true`、`content=""`，并给 `note`「仅元数据：不得把 abstract 当结论引用」。
- **ID 歧义（02 §7）**：入参优先当**全局存储 ID**。裸 raw_id 唯一命中则直接用；跨 topic 多命中时**不得静默取一条**，返回 `{error:"ambiguous_doc_id", input, candidates[], hint}` 且退出码 1。实测：`2210.04644` 同时存在 papers 与 `cbac:2210.04644`，故必须列候选。

### 6.7 `kb-eval`（M3 起，M5 默认集扩 50 条）

```text
kb-eval [--set knowledgebase/_meta/eval/eval_v2.jsonl] [--top-k 10] [--refresh-baseline] [--pretty]
```

- 返回 EvalReport：`{n, top_k, quality, "recall@10", "mrr@10", baseline{...}, l0_cases{n,new_hit,baseline_hit}, regressions[], diagnostics{relaxed_quota_recall@10, use_vector, fusion, cross_lingual{n,recall@10}, deep_l3_gate{n,min_l3_in_top10,queries_with_l3_ge_4}}, per_query[]}`，并落盘 `data/kb/eval_report_{时间戳}.json`。
- **默认集 = `eval_v2.jsonl`（50 条）**，缺失时回退 `eval_v1.jsonl`；只跑 M3 那 30 条时显式 `--set knowledgebase/_meta/eval/eval_v1.jsonl`。
- 基线 = 同 query 调 `backend.services.ragsearch.service.search_all(query, top_k)`；结果缓存 `knowledgebase/_meta/eval/eval_baseline.json`，只补采缺失 query（基线失败记 0 命中，不抛穿）。
- 评测集 50 条 = eval_v1 30 条原样保留 + 10 英文机械派生 + 10 跨语言（中文 query → 英文 L3 论文，`cross_lingual:true`）；
  两种新增标注方法与"不按检索表现择优"的纪律见 02 §12。
- 退出码：达标 0，未达标 1（`pass` = recall≥基线 且 L0 反例全中）。

### 6.8 `kb-promote`（M5）

```text
kb-promote DOC_ID... [--to-tier 2|3] [--apply] [--no-strict] [--pretty]
```

- 返回 `{to_tier, apply, strict, requested, ok, promoted[], exempt[], rejected[], details[], written[]}`。
- **D27 回链门槛**：`to_tier=2` 必须有 `[L3:路径#chunk]` 回链，且**路径解析到该 doc 本人的 tier=3 版本**、`#chunk` 为数字/cN 时**块序号必须真实存在**；否则 `rejected[].reason="missing_backlink"`（退出码 1）。`to_tier=3` 要求存在 tier=3 版本（`missing_l3_version`）。
- **存量豁免**：`status='legacy_l2'` 的 5 条 dense 放行且**保持 legacy_l2**（不因一次调用被抹掉）；名单是冻结文件 `knowledgebase/_meta/config/legacy_l2.json`，catalog 入库/`kb-rebuild` 时按它复现。
- 默认 `apply=False` 只校验；`--apply` 才把通过的写成 `status='active'`；默认 `strict`（任一不通过则整批不写），`--no-strict` 只写通过者。**绝不改 md 源文件。**

### 6.9 `kb-tag`（M6）

```text
kb-tag DOC_IDS [--add a,b] [--remove c] [--pretty]
```

- 返回 `{applied, requested, add[], remove[], updated[], changed[], noop[], ambiguous[], not_found[], errors[], md_written}`。
- **只写 kb.db**：更新 `documents.tags` + 同步 `kb_fts`，**绝不改 md 文件**（`md_written` 恒为 0）。改 md frontmatter 请用 `kb-tags clean`。
- `add` 的标签按**每个 doc 自身 topic** 的 confirmed 词表做 `canonicalize`（alias → canonical）。
- 未知 id → `not_found`（退出码 1）；裸 id 跨 topic 命中 → `ambiguous_doc_id` + `candidates[]`（退出码 1，不静默取一条）；`add`/`remove` 至少要给一个（`invalid_argument`）。

### 6.10 `kb-batch`（M6；02 §7 早有此契约，M1–M5 未实现，M6 补齐）

```text
kb-batch open [--round-id R] [--topic T]
kb-batch add ROUND_ID DOC_ID...
kb-batch confirm ROUND_ID --topic T [--tags a,b]
kb-batch list [--status open|confirmed|cancelled]
```

- 返回：`open/add` → 批次详情 `{round_id, topic, label, status, created_at, confirmed_at, item_count, items[], added[], unknown_doc[]}`；`confirm` → 追加 `{topic_applied, tags_applied[], written_docs, tag_report}`；`list` → `{kind:"batches", count, by_status, items[]}`。
- **候选区语义（D11/D12）**：`open`/`add` 只动 `batches`/`batch_items`，**不影响检索**；`confirm` 才把 `topic` 与 tags 落到本批 `documents`（tags 复用 `tag_docs`，同样只写 kb.db）。
- `add` 对不在库的 doc_id 返回 `unknown_doc`（不静默吞）；`confirm` 空批 → `empty_round`、重复确认 → `already_confirmed`、topic 空 → `invalid_argument`；均退出码 1。
- 写纪律：所有写走 `db.write_retry`（短事务 + `busy_timeout` locked 重试 3 次）。
