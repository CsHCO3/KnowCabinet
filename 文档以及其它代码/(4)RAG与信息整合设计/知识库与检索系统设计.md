# 知识库与检索系统设计（当前状态 + 扩展指南）

> **权威活文档 · 版本 2026-10-20**。内容与代码逐项核对（`ragsearch/registry.json`、`ragsearch/engine/*`、`backend/services/ragsearch/service.py`、`backend/services/kb/*`、`data/`、`.data/`、`data/rag.db`）。
> 定位：**接任 AI 的单一入口文档**——看懂"数据怎么组织、怎么检索、怎么加新内容"。文档总索引见 `00-交接说明.md`。

## 0. 一句话

系统分三层：`knowledgebase/`（**够格入库的 md**，按 `tier` 分密度：原文/轻整理/提炼）+ `data/`（**原始/二进制/处理区**，不入库）+ `.data/` 与 `data/*.db`（**处理记录与检索记录**）。检索有两条链路并存：`ragsearch` 的 BM25/FAISS 引擎（按 `registry.json` 把每个库映射到目录，8 字段 frontmatter 支撑过滤/分组/加权），以及第 9 节的 `kb` 统一检索层（FTS5 + 向量 + 交叉编码器重排）。**加一种新内容 = 放文件 + 写 frontmatter + registry 加一条**，引擎零改动。

**三条硬规矩**（2026-10-20 与库主确认）：

1. **凡参与检索的内容必须在 `knowledgebase/`**。`data/` 只放处理过程与二进制；把它整个删掉，已提炼的知识（md + kb.db 重建）不受影响。
2. **`knowledgebase/_meta/` 放"系统的规则与记录"**——分区表、分级表、评测集、测试基线、验收日志、词表。它们不是内容、不参与检索，但缺了就没法扫描或没法回归，所以不能放在可随时清理的 `data/` 里。该目录不在 registry 里，不会被当成库扫进去。
3. **`data/kb/` 只留 `kb.db`**（派生层）；视频隔离名单等流水线状态归 `data/bilibili/`。

**分区与目录的唯一规则**：一个目录 = 一个 registry 条目 = 一个 `topic`。
- 分区是**一级身份**：`default` / `CBAC` / `dairy` 各自独立；分区内再按内容形态分 `papers` / `dense` / `web` / `research_projects`；社媒不归分区，统一放 `community\<来源>\`。
- **没有下载的论文不占文件夹**：正文在 `<分区>\papers\<id>\`，纯题录统一扁平存 `<分区>\papers_meta\<id>.json`（库主 2026-10-20 裁定，原 1453 个空文件夹已拆平）。
- 目录名不是"分类标签"，**分类靠 `topic` 元数据字段**表达（`knowledgebase/_meta/config/topics.json` 把 kb 目录映射到 topic）。同一篇论文若在两个分区各存一份，会产生两条互不相认的记录（`papers:{id}` / `cbac:{id}` 就是撞名痕迹）——2026-10-20 已清干净，库里不再有带前缀的 doc_id。

**原则**：`knowledgebase/` 只放 md 且分层按信息浓度；`data/` 装原始与中间态；记录（谁来的/处理到哪/我问过什么）分开存。

## 2. 检索系统与 registry

### 2.1 registry.json（KB 登记表）——现状

```json
{
  "dense":  {"path": "knowledgebase/dense", "title_weight": 0.5, "body_weight": 0.5, "tag_boost": 0.2},
  "papers": {"path": "knowledgebase/full/papers", "title_weight": 0.5, "body_weight": 0.5, "tag_boost": 0.2},
  "runoob": {"path": "knowledgebase/full/web/runoob"},
  "newapi": {"path": "knowledgebase/full/web/newapi"},
  "CBAC": {"path": "knowledgebase/full/CBAC/papers", "title_weight": 0.5, "body_weight": 0.5, "tag_boost": 0.2},
  "dairy_digital_twin": {"path": "knowledgebase/full/dairy_digital_twin", "title_weight": 0.5, "body_weight": 0.5, "tag_boost": 0.2},
  "research_projects": {"path": "knowledgebase/full/research_projects", "title_weight": 0.5, "body_weight": 0.5, "tag_boost": 0.2}
}
```

> 2026-10-20 起 `docs` 与 `1-3-VERA`/`3-IMA` 四条登记已删除：前者的 44 篇论文已并入 `full/papers`、3 篇学位论文与 `CBAC/papers` 里的记录重复；后两者在 M2 就只删了派生层，本轮连目录层一并下线（正文与项目调研已归并，其余归档在 `data/_kb_legacy/20261020-*`）。

- 相对路径以**项目根**解析（`ragsearch/config.py`）。注册即入库：一个目录 = 一个可搜索库。
- 可选权重：`title_weight`/`body_weight`/`tag_boost`；可选 `include`/`exclude` glob（**注意 fnmatch 不支持 `**`**）。
- 索引目录 `ragsearch/index/{kb_name}/`（构建产物，`.gitignore`，删了会自动重建）。

### 2.2 引擎（`ragsearch/engine/`，BM25）

- **索引**：`DocIndexer(docs_dir, index_dir, weights, include, exclude)`；manifest 增量——md 增删改后**下次搜索自动重建**（首次略慢），无需显式 reindex。
- **idf 修复**：`_BM25OkapiFixed`（修 rank_bm25 对"词在恰好一半文档"时 idf=0 的 bug），构建/加载均用它。
- **frontmatter 8 字段**：`id / title / source / section / authors / year / tags / source_type`（详见 §4）。标题回退链：frontmatter `title` → 首个 `# ` 行 → 文件名。doc_id：frontmatter `id` → 路径首段目录名 → 文件名去扩展名。
- **过滤**（`filter_results`）：`section`/`authors` 子串、`tags` 任一命中、`year`/`source_type` 精确（均大小写不敏感，条件 AND）。
- **分组**（`group_results`）：按 `doc_id` 折叠（论文多版本合成一条）。
- **重排/去重**：`Reranker(RERANK_BACKEND)`（cosine 可选，默认不开启）+ `dedup_results`。

### 2.3 服务入口（`backend/services/ragsearch/service.py`）——对外唯一门面

```python
load_registry() -> dict[str, str]      # 重载 registry.json → {kb: 绝对目录}（改 registry 后必须调）
rebuild_kb(name) -> dict               # 强制重建某库索引；未登记/目录不存在返回 error 不抛错
search_kb(name, query, top_k=10, *, section, tags, year, authors, source_type, group_by_doc) -> list[dict]
search_all(query, top_k=10, *, ...同左) -> list[dict]     # 跨库，filename 带 [kb] 前缀
get_status() -> dict                   # {kb: {doc_count, docs_dir, index_ready}}
search_folder(folder, query, ...)      # 任意文件夹临时 BM25（不登记、不进库），索引缓存 ragsearch/index/_tmp/
fetch_paper(id) -> dict                # 单篇全文：dense 浓缩 → full 最优版 → data/...pdf（未解析标记）
```

返回 `SearchResult` dict：`{filename, doc_id, title, snippet, score, rank, section, source, authors, year, tags, source_type}`；`group_by_doc=True` 时返回 `{doc_id, title, score, version_count, versions:[...]}`。

### 2.4 检索链路

```
rag-ask / /api/rag/query / search_kb ──► service ──► DocIndexer(registry 目录).search
        ──► filter_results(section/tags/year/authors/source_type)
        ──► Reranker.rerank ──► dedup ──► [group_by_doc] ──► 返回
```

## 3. 数据流：内容进来 → 可检索

```
①找到/收集   ②转换(marker/mineru→md)  ③[翻译→cn_paper]  ④[识图→*_ocr]  ⑤浓缩→condensation  ⑥晋升
   ↓              ↓                        ↓                   ↓             ↓                  ↓
 data/(二进制)   data/remote_pdf/ 多版本    完整版收敛到 full/    甄选          密集 dense/paper/
```

- **论文**：`paper-search`（多平台搜索：Crossref/OpenAlex/arXiv/Google Scholar/万方/知网/ePrint → 入库元数据 → 可选下载）→ `data/pdfs/` → 远程转 md（`pdf`/`mineru` + `warmup`）→ `archive` 归档收敛到 `knowledgebase/full/papers/{id}/`（版本优先级见 §6）+ 二进制移入 `data/papers/{id}/` → `condense` 生成 `condensation.md` 并晋升 `dense/paper/{id}.md`。
- **视频**：`video-import`（采集→提取字幕+摘要→晋升 `dense/video/{bvid}.md`），元数据在 `data/bili.db`。
- **文档**：`import-papers`/手动放 `knowledgebase/full/docs/{stem}/`。
- **网页/教程**：手动放 `knowledgebase/full/web/{site}/`（runoob/newapi 即此）。
- **索引**：归档/浓缩收尾自动 `rebuild_kb("papers"|"videos"|"docs")`；引擎 manifest 也能下次搜索时自动建。

## 4. 元数据契约（frontmatter 8 字段）

引擎只认这 8 个字段（`normalize_meta` 白名单，其余丢弃）。**缺失字段 = 该维度无法过滤/分组**，但可检索（标题回退）。

| 字段 | 含义 | 论文示例 | 生成规则（论文） |
|---|---|---|---|
| `id` | doc_id（身份） | `2210.04644` / `10.1109_xxx` | arxiv_id 或 DOI slug |
| `title` | 标题 | … | 元数据/回退 |
| `source` | 来源 URL | `https://arxiv.org/abs/...` | 元数据 |
| `section` | 分类大类 | `Security & Cryptography` | primary_category 映射（无映射原样） |
| `authors` | 作者（逗号分隔串） | `Hao Xu, ...` | 元数据 |
| `year` | 年份（字符串） | `2023` | 元数据 |
| `tags` | 逗号分隔集合 | `cs.CR, 浓缩关键词` | 3 路合并（arXiv cat ∪ OpenAlex topics ∪ 关键词行） |
| `source_type` | 内容类型 | `paper` | 见下 |

**source_type 取值**：`paper` / `video` / `docs` / `web` / `social` / `chat` / `project`（开源项目调研）/ `research_project`（论文调研项目）。引擎把它当**不透明字符串**做精确过滤——加新类型不需要改引擎，只要统一用新值 + 前端/文档同步。

`tags` 解析宽松：支持 `[a, b]`、`a, b`、空格分隔、单值（`parse_tags`）。frontmatter 必须从文件第 0 字节 `---` 开始。

## 5. 【扩展指南】加一种新内容类型（重点）

> 目标示例：接"网页/网站"内容（`source_type=web`）。**两条路**：A 塞进现有库（最快）；B 建新库（独立可过滤）。多数情况 A 够用。

### 路 A：塞进现有库（最快，零 registry 改动）

1. 把 md 放进已注册目录，如 `knowledgebase/full/web/runoob/`。
2. 每篇补 frontmatter 至少 `title` + `source_type: web`（见 §4；不写也能搜，只是不能过滤）。
3. 完事。下次搜索自动索引；跨库 `search_all` 已包含。

### 路 B：建新库（独立 KB，可单独过滤/加权）

1. **放文件**：`knowledgebase/full/web/<site>/`（或新类型 `knowledgebase/full/<type>/<name>/`）。
   - 每篇一个 md。**doc_id 默认取路径首段目录名**——若一个目录多篇小页，给每篇 frontmatter 写 `id`，或一页一目录。
2. **写 frontmatter**（8 字段规范见 §4）。至少 `title` + `source_type`。
3. **registry.json 加一条**（相对项目根）：
   ```json
   { "<kb_name>": { "path": "knowledgebase/full/web/<site>", "title_weight": 0.5, "body_weight": 0.5, "tag_boost": 0.1 } }
   ```
4. **重载 registry + 建索引**：改完 registry 后运行
   ```bash
   python -c "from backend.services.ragsearch.service import load_registry, rebuild_kb; load_registry(); print(rebuild_kb('<kb_name>'))"
   ```
   ⚠️ **web 服务进程不会自动读新 registry**（注册表只在启动时加载）——改 registry 后需重启服务或调 `load_registry()`。用上面这行即可，无需重启。
5. **验证**：
   ```bash
   python -m backend.main rag-ask "测试词" --kb <kb_name>      # 单库
   python -m backend.main rag-ask "测试词"                      # 跨库（自动包含新库）
   ```

### 路 C：库间迁移（`rag-migrate`，2026-08 新增）

建好项目库后，用 `rag-migrate` 把文献在"通用库 ↔ 专用库"之间**批量双向移动**（不用手动搬目录）：

```bash
# 干跑看清单（不落盘）
python -m backend.main rag-migrate --from papers --to proj_cbac --tags "实验室内" --dry-run
# 复制（源保留）
python -m backend.main rag-migrate --from papers --to proj_cbac --tags "实验室内"
# 移动（复制后删源）—— 真正的"迁出"
python -m backend.main rag-migrate --from papers --to proj_other --tags "<项目tag>" --move
```

- **迁移单位 = 目录级**：`{id}/paper.md` + `images/` + `metadata.json` 整体搬。
- **筛选**：复用 §4 的 8 字段（`--ids`/`--tags`/`--section`/`--source-type`/`--year`），语义同 `filter_results`。
- **冲突**：目标已有同名 id 默认跳过，`--force` 覆盖。
- **日志/回滚**：`data/migrate_log.jsonl` 记录每次动作。
- **索引**：BM25 由 manifest 自动感知无需手动；dense 需手动 `ragsearch-index --kb <源>` 和 `--kb <目标>`。
- **典型用法**：毕设主力留默认 `papers` 库，把混入的其他项目迁到 `proj_other`；需给某项目独立库时用 `--copy` 迁出（papers 保留）。

### 完成后可选的接线（让新类型"一等公民"）

- **过滤**：`rag-ask "…" --source-type web`；`/rag` 页左上 `source_type` 下拉加新值（`frontend/templates/rag.html`）。
- **dense 晋升**：若内容值得语义检索（L1），把浓缩版放 `knowledgebase/dense/<type>/<id>.md` 并写 8 字段。
- **dense 段落语义检索（已接线）**：`ragsearch-index`（bge-m3+FAISS）把知识库 md 分块嵌入成段落向量库（存 `ragsearch/index/vector/{kb}/vs`），`rag-ask "…" --dense` / API `retrieval=dense` 走它——**跨语言、段落粒度**，弥补 BM25 词法匹配不到英文内容的短板。⚠️ 依赖 faiss/bge-m3（只装 conda `infosystem` 环境），且每库需先 `ragsearch-index --kb <name>` 建索引、新增论文后重建。
- **处理记录**：视频/论文有 `metadata.json` + `.data/tasks.json` 阶段记录。网页类一般不需要；要的话按对象在 `data/` 下建记录目录。
- **前端入库管线**：若想走 UI（像 /videos 那样），参考 `api/services/bilibili_service.py` + `api/routers/bilibili.py` 的收集→提取→入库模式另起一套。

### 约束与坑（必读）

1. **UTF-8**：md 必须 UTF-8（读码 `utf-8`）。
2. **fnmatch 不支持 `**`**：registry 的 include/exclude 别用双星。
3. **frontmatter 在文件开头**：第 0 字节 `---\n`，否则当普通正文。
4. **doc_id 冲突**：目录式 doc_id 在"多篇共目录"时会撞——用 frontmatter `id` 或一页一目录。
5. **空目录**：`rebuild_kb` 对空/缺目录返回 `error`（不抛），搜索跳过该库。
6. **权重语义**：`title_weight`/`body_weight` 是 BM25 字段权重，`tag_boost` 命中 tags 加分。教程类标题信号强可 `title_weight: 0.6`。
7. **别把二进制放 knowledgebase/**：L3 二进制进 `data/`。
8. **改 frontmatter 后**：不需要手动 reindex——manifest 自动感知；但改 registry 路径/新增库必须重载 registry（见路 B 第 4 步）。

## 6. 论文特殊机制

- **版本优先级**（`archive` 收敛）：`cn_paper_ocr(4) > paper_ocr(3) > cn_paper(2) > paper(1)`，`full/papers/{id}/` 只留最优 1 版，低级副本移 `data/_kb_legacy/{id}/`。
- **浓缩独立**：`condensation.md` 与完整版并存，晋升 `dense/paper/{id}.md`。
- **分组折叠**：检索 `group_by_doc=True` 把同论文多版本合成一条（共享 doc_id=目录名）。
- **取全文**：`fetch_paper(id)`：dense 浓缩 → full 最优版 → 纯 PDF（标记 `unparsed`）。
- **PDF 归档**：`archive_pdf` 支持 arxiv_id、DOI-slug、ePrint-slug（`YYYY-NNNN`）三种 id；`paper-search` 下载成功后会自动调用归档，下载文件命名 `{entry_id}--{标题}.pdf` 优先按 entry_id 归到 `data/papers/{entry_id}/paper.pdf`。
- **ePrint 源**：密码学预印本，全开放 PDF 直下；记录带独立 `eprint_id`（如 `2023/708`），归档 id 用 slug 化 `2023-1194`，frontmatter `source` 指向 `eprint.iacr.org/{eprint_id}`；`category` 即密码学 7 类存到 `venue`。可用 `paper-search --only-sources eprint` 单独搜。

## 6.5 代码项目入库（`project-import`，与论文同组）

**结构**：调研分区（1-3-VERA、3-IMA…）下 `papers/` 存论文、`projects/` 存代码项目，registry 各注册一个 KB（`{分区}` + `{分区}-projects`）。`rag-ask --kb {分区}-projects` 单独检索项目，`search_all` 跨库同时命中论文+项目（以调研为单位并行）。

```
full/{调研分区}/
  papers/{论文id}/        # 论文
  projects/{项目id}/      # 项目：{owner}-{name}/project.md + metadata.json
  _candidates.md          # 分区级项目候选清单（未验证，不参与项目 KB 索引）
```

**frontmatter**（8 标准字段，`source_type: project`）：`title / source(仓库URL) / section / tags / year`。
**metadata.json 富字段**：`id, url, host, owner, license, language[], stars, forks, archived, last_commit, latest_release, observed_at, last_verified, verified, status(active/candidate/...), section, tags, core_algorithms[], base_libraries[], upstream_projects[], build_deps[], language_stack[], capabilities[], eco_layer, deps_lower[], supports_upper[], competitors[], relations[], provenance, manual_fields, conflicts`。

**命令**：`project-import <GitHub/GitLab/npm URL 或项目名> --kb 1-3-VERA [--section --tags --force]`。
- host 自动识别：github（`gh api`，已登录 token）/ gitlab（REST）/ npm（registry）/ gitee（REST，search 需 `GITEE_TOKEN`）/ 纯名字（先 `gh search repos` 找 GitHub，否则 Bing 候选）。
- 拉取元数据 → 建 `projects/{id}/` 骨架（project.md + metadata.json）→ 未验证写 `_candidates.md`。
- 子命令：`--list-stale N`（列出 last_verified 超期）、`--force`（覆盖）。

## 9. 私域知识库框架（派生层 + 统一检索）

> **真相源不变**：`knowledgebase/` 下的 md 与 `metadata.json` 是唯一事实；`data/kb/kb.db` 只是**可删除重建**的派生目录层，`kb-rebuild` 能从文件重建出与删除前一致的状态。
> 实施细节与决策编号见 `知识分级重构与缺陷登记/`（D44–D55），里程碑日志见 `knowledgebase/_meta/reports/acceptance/M{0..8}.log`。

### 9.1 派生层的六张表

| 表 | 内容 |
|---|---|
| `documents` | 一篇文档一行：topic、source_type、title、abstract、authors、year、venue、doi、tags、org_marks、arxiv_cats、stage、best_tier、status |
| `versions` | 一个载体一行：`tier` + `kind`（kind→tier 的映射见 9.2）+ 文件路径 + content_hash + 字数 |
| `chunks` | 切块清单：text、content_hash、model_id、embedded_at（version 外键 CASCADE） |
| `kb_vec` | sqlite-vec `vec0` 容器，chunk_id 主键 + float1024 |
| `kb_fts` | FTS5（jieba 分词，unicode61 去重音），列 title/abstract/tags/body，权重 3.0/1.5/2.0/1.0 |
| `batches` | 候选区（外搜结果先攒着，确认后才写 topic/tags，不影响检索） |

`knowledgebase/_meta/config/` 下是几个**真相源级**的配置文件，改它们比改代码重要：

| 文件 | 作用 |
|---|---|
| `tiers.json` | **kind → tier 的唯一事实源**。查不到的 kind 直接报错中止扫描（D45），不再静默兜底 |
| `topics.json` | KB 名 → topic 的映射（`papers` / `cbac` / `dairy` / `research-projects`），以及外部路径 |
| `scope.json` | **检索范围排除表**（D53）。当前 `exclude_kinds=["web_note"]`：网页爬取类整篇不参与检索，数据与向量全部保留，删掉这一行即可加回 |
| `legacy_l2.json` | D27 存量豁免名单（无回链的旧 L2） |

### 9.2 分级口径：`tier` 是**信息密度**，不是取证保真度（D44）

| tier | 含义 | 典型 kind |
|---|---|---|
| 0 | 线索：只有元数据，没有正文 | `meta` |
| 1 | 原文：逐字记录 | `paper`、`cn_paper`、`paper_ocr`、`chat_raw`、`subtitle`、`note`、`web_note`、`原文留存` |
| 2 | 轻整理：一次加工（压缩、翻译、格式化） | `condensation` |
| 3 | 提炼：二次加工，跨源对照后的结论 | `chat_distill`、`tieba_distill`、`analysis`、`synthesis` |

两条铁律：

1. **kind → tier 只查 `tiers.json`**。新增一种 kind 必须先登记档位，否则扫描中止（D45）——这条是为了防止再出现"文件名即 kind、未登记就默认 L1"的老毛病（P-05/P-02）。
2. **"能不能引原话"从 tier 里拆出来**，由 `evidence.quote_from` 表达（D44）：

| `quote_from` | 判据 | 含义 |
|---|---|---|
| `raw` | 该文档存在 tier=1 版本 | 可以 `kb-fetch --tier 1` 取逐字原文，`verbatim_allowed=true` |
| `derived` | 只有 tier≥2 版本 | 只能转述，不能当原话引 |
| `none` | 只有 meta | 只能断言"存在这篇"，**禁止**把 abstract 当结论 |

旧字段 `has_l2 / has_linked_l2 / must_quote_l3 / has_l3 / quote_fallback / l3_chunk_ids` **已全部移除**，替换为 `quote_from / quote_tier / quote_kind / verbatim_allowed / quote_chunk_ids`。

管理类文件（`_索引.md` 等）不入库（D46）；目录残渣块在 chunk→doc 折叠前剔除（`chunkq.partition_toc`）。

### 9.3 检索链路（`backend/services/kb/query.py::ask`）

```
确定性过滤 → 两路召回 → 每档配额选（保召回）→ 跨档统一尺度重排（保排序）→ 交叉编码器重排 → 证据标注
```

1. **确定性过滤**：topic / tags / org_marks / source_type / year / tier 区间 / stage / status，
   外加 **D53 范围排除**（`NOT EXISTS` 子查询按 version kind 整篇排除，默认排除 `web_note`）。
2. **两路召回**：
   - FTS5：tier=0 只搜元信息列，tier≥1 搜全列（分词必须走 `ftx.tokens()`，与写入端同一套 jieba 搜索引擎模式，否则中文查询会静默 0 命中）；
   - 向量：仅 `deep` 模式开启——query 嵌入一次（进程内常驻 bge + query 级缓存）→ 全库 chunk KNN 取 200 块 → 用确定性候选 doc 集在应用层收敛（vec0 不支持按 doc_id 过滤）→ chunk→doc 折叠（同 doc 取最高块分或 top3sum）。
3. **每档配额选**：每档内 min-max 归一化 + 向量保底名额（`fusion=reserve`），按配额表取人。

   **这一步只决定"谁入选"，不决定顺序**——这是 D52 的核心：用级内归一化保护召回，避免"某一档唯一的好命中"被别的档挤掉。
4. **跨档统一尺度重排（D52）**：对已入选的条目，用两条支路在**全库候选**上的极值重新归一化，取较高者，再乘档位先验（L0 空壳 ×0.30），据此排序。这样消掉了"每档最佳都等于 1.000"的并列假象。
5. **交叉编码器重排（D55）**：召回池放大到 `top_k × 3`，把 `(查询, 标题+命中片段)` **成对**喂给 `bge-reranker-v2-m3`（基座与 bge-m3 同源，多了分类头），按 logit 排序后截 `top_k`。
   - 打分只用于**同一候选集合内部**排序，绝对分值不跨集合比较（中文对偶的 logit 常为负，阈值无意义）；
   - 模型缺失 / 无 GPU / 显存异常 → 退回"不重排"，且**先判可用性再定池**，避免降级时池子白放大；
   - `KB_RERANK=0` 可全局关闭（对照实验、无 GPU 机器）。
6. **证据标注**：每条结果带 `quote_from / quote_tier / quote_kind / verbatim_allowed / l0_only / legacy_l2`，命中块带 `chunk_id` 可直接 `kb-fetch --chunk-ids`。

### 9.4 配额表（D49）

`top_k=10` 的绝对配额；`top_k≠10` 时按比例缩放，每档至少 1 个名额。

| mode | L0 线索 | L1 原文 | L2 轻整理 | L3 提炼 | 语义 |
|---|---|---|---|---|---|
| `browse` | 6 | 2 | 1 | 1 | 盘点：先看有哪些东西 |
| `balanced` | 2 | 3 | 3 | 2 | 日常问答 |
| `deep` | 1 | 7 | 1 | 1 | 深挖原文：细节在 tier=1 |

D49 把 deep 从 `1/1/1/7` 改成 `1/7/1/1`：密度序下"细节"就是原文。**配额现在只影响候选构成**（D55 之后最终顺序由重排决定），所以它的权重比 D33 时代低，但仍是"每档都有代表"的护栏。

### 9.5 入库质量闸门（D51 + D54）

视频摘要会写进检索库，所以字幕必须可信：

| 闸门 | 判据 | 命中动作 |
|---|---|---|
| 长度 | 字幕正文 < 200 字 | 不生成摘要、不晋升 dense，记 `subtitle_too_short` |
| 主题 | `bge-reranker-v2-m3` 给 `(标题, 字幕)` 打分，logit < 0 | 记 `subtitle_off_topic`（note 里带 logit） |
| 抓取失败 | `no_subtitle` / `no_text` | 记入待验清单 |

待验清单是 `data/videos/quarantine.json`；判据不可用（模型缺失）时**跳过闸门**，绝不误杀。标定数据见 `06-字幕主题自检标定.md`：真字幕 logit +2.65~+5.96、错配字幕 −8.42~−3.53，中间空 6.2 个点。
