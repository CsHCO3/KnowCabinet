## 七、检索入口只剩一条（2026-10-21 下线记录）

| 已删除 | 原来是什么 | 现在用什么 |
|---|---|---|
| `rag-ask` | 旧 BM25 检索 CLI（还会打 HTTP 到 /api/rag） | **`kb-ask`**（读 `data/kb/kb.db`）、取原文用 **`kb-fetch`** |
| `ragsearch-index` | 旧 FAISS 向量索引重建 | **`kb-scan` → `kb-embed`** |
| `/rag` 页 + `/api/rag/*` | 检索 + LLM 成段回答（问答页） | 无（不做总结；需要回答就让 agent 读片段/取原文） |
| `ragsearch/index/vector/**`（150.9 MB） | FAISS 向量副本 | `kb.db` 的 `kb_vec`（sqlite-vec） |
| `ragsearch/index/{_tmp,docs,1-3-VERA,3-IMA,…}` | 废弃库索引 + 临时产物 | 已删 |

**为什么删**：那是第二份索引副本，需要手动重建、长期不同步（8/19 的向量到 10 月还在被 `/rag` 用）；
而 AI 要的是**带出处的片段**，不是二手总结——总结会额外调一次 LLM、有损、且丢了 doc_id/块号没法回源。

**保留下来的**：`ragsearch/index/<在役库>/bm25_index.pkl`（`kb-eval` 拿它当旧基线、入库流程会自动重建）、
`ragsearch/engine/{chunker,bge_embed,document,filter,dedup,reranker}`（kb 目录层依赖这些库函数）、
`rag-folder`（任意文件夹临时检索）。**不要**再删这几样。
